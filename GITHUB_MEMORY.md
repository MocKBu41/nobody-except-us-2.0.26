## КАНОНИЧЕСКАЯ ЛОГИКА БОТА

Главный файл поведения бота: `BOT_MEMORY/BOT_LOGIC_CURRENT.json`.

Он создан из присланной пользователем плиточной схемы `BOT_logic_editor.html` от **2026-09-14** и является **источником истины для поведения NEU BOT**.

Обязательное правило для любых будущих изменений поведения:

1. Сначала прочитать `BOT_MEMORY/BOT_LOGIC_CURRENT.json`.
2. Если пользователь меняет правило поведения, приоритет, условие, дистанцию, состав, покупку/вызов юнита или переход состояния — **обязательно внести это изменение в `BOT_MEMORY/BOT_LOGIC_CURRENT.json`**.
3. Затем синхронизировать код текущей версии бота с обновлённой логикой.
4. Если изменение ещё не проверено в игре — статус `НУЖЕН ТЕСТ`.
5. После теста прочитать новый лог из `/LOG/`, подтвердить/отклонить изменение и обновить память.

Подробное правило хранения находится также в `BOT_MEMORY/README.md`.

## ОБЯЗАТЕЛЬНЫЕ КОМПОНЕНТЫ КАЖДОЙ НОВОЙ ВЕРСИИ БОТА

Начиная с исправления BOT 2.0.1 нельзя выпускать новую версию только из `bot.lua/core/logic`, если это приводит к потере инструментов проекта. В пакет и проверку версии обязательно входят:

- рабочая подписка на `BotApi.Events.GameStart`, `GameEnd`, `Quant`, `GameSpawn`;
- телеметрия для визуализации поведения;
- `bot_visualizer.html` либо совместимый новый визуализатор;
- координаты флагов/точек карт (`_flag_points_final.json`, `_map_points_index.json` или актуальная замена);
- координаты SpawnPoint сторон A/B (`_spawn_points_index.json` или актуальная замена);
- проверка совместимости формата телеметрии с визуализатором.

Эти компоненты нельзя молча удалять при создании следующей версии.

## BOT 2.0 — ОШИБКА, ТЕСТ 2026-09-15

Лог: `/LOG/game_bot 2.0.log`.

Подтверждено логом:

- `bot.main.lua -> bot.lua -> bot.core.lua -> bot.logic.lua` успешно загружались;
- выводилось `BOT 2.0 ACTIVE`;
- после этого отсутствовали `START BOT 2.0`, `UNITS`, `QUEUE`, `SPAWN`, `STATE`, потому что в `BOT_GPT/v2_0/bot.logic.lua` были определены `onGameStart/onGameStop/onGameQuant/onGameSpawn`, но были потеряны вызовы `BotApi.Events:Subscribe(...)`;
- следовательно, игровая логика BOT 2.0 не запускалась;
- из пакета BOT 2.0 также были ошибочно исключены визуализатор и координатные наборы, присутствовавшие в предыдущих версиях.

Статус `BOT_GPT/v2_0`: **ОШИБКА / НЕ ИСПОЛЬЗОВАТЬ КАК АКТУАЛЬНУЮ ВЕРСИЮ**.

Исправляемая линия: `BOT_GPT/v2_0_1/`.

## Текущая каноническая стратегия

Поведение остаётся из `BOT_MEMORY/BOT_LOGIC_CURRENT.json`:

- OPENING: `infantry -> recon -> tank -> mech_inf`;
- экономика: 1200 BP, +20 BP/сек, резерв 200 BP;
- Spawn retry 2 сек, timeout 60 сек;
- после OPENING -> EXPAND;
- разные цели: минимальная нагрузка, при равенстве нейтральный флаг приоритетнее;
- infantry/mech_inf получают приказы раньше техники;
- tank/recon/attack_heli следуют с задержкой 10 сек;
- потеря recon/tank/mech_inf/attack_heli -> WAIT_REINFORCEMENT и замена;
- преимущество по флагам >=1 -> DEFEND; потеря преимущества -> EXPAND;
- отсутствие обычной infantry -> пополнение;
- attack_heli только при подтверждённом точном количестве танков противника >=3; boolean EnemyHasTanks недостаточен;
- максимум 1 attack_heli;
- артиллерия отключена;
- unmatched/passenger squads не добавлять автоматически.

## Визуализация и координаты

Последняя полная визуализационная база до регрессии находится в `BOT_GPT/v1_27/`: `bot_visualizer.html`, `bot.telemetry.lua`, `bot.mapdata.lua`, `_flag_points_final.json`, `_map_points_index.json`.

Новый отдельный индекс SpawnPoint находится в корне: `/_spawn_points_index.json`. Формат `mowas2_spawn_points_index_v2`; на момент создания индекс содержит 46 battle_zones файлов, 44 карты со spawn points и 548 SpawnPoint. Записи содержат `team`, `x`, `y`, поэтому A/B следует отображать непосредственно из него.

ВАЖНО: координаты нужны для визуализации на всех индексированных локациях, но бот не должен автоматически использовать геометрию карты, если карта определена неоднозначно только по набору имён флагов. Анализ боя 7 показал ложный match `f1..f11`. При неоднозначности визуализатор должен позволять выбрать карту вручную, а бот — не принимать ложные координатные решения.

## Не считать реализованным до отдельного подтверждения

- Высадка пехоты из БМП/БТР: `crew_emit` найден, но безопасный BotApi/Lua метод высадки только десанта не подтверждён.
- Пехотное развёртывание примерно за 100 м и фронт с интервалом 5–6 м.
- Остановка танка примерно в 50–100 м от точки.
- Остановка БМП/БТР примерно в 20–50 м от точки.
- Реальное координатное движение отрядов без проверенного coordinate bridge.
