# NEU BOT v1.11

Версия основана на v1.10 и меняет стартовый захват точек.

## Новое правило старта

В начале матча нейтральные точки захватывают **только юниты, у которых в `t(...)` есть тег `pointstart`**.

Другие роли, включая `recon`, больше не имеют права захватывать обычную нейтральную точку на старте.

Схема:

- определяется список нейтральных флагов на старте;
- он сортируется по геометрии карты/расстоянию от спавна;
- на **каждую стартовую нейтральную точку создаётся отдельный `pointstart`-отряд**;
- правило жёсткое: **1 отряд = 1 точка**;
- после захвата своей точки этот отряд не переназначается на следующую стартовую точку;
- fallback на обычную infantry/vehicle_supporter отсутствует.

Если в текущей стороне нет ни одного юнита с тегом `pointstart`, бот пишет:

```text
[NEU-BOT] POINTSTART ERROR candidates=0; no fallback is allowed
```

## Потеря pointstart-отряда

Если назначенный `pointstart`-отряд погиб, пока его точка ещё не принадлежит боту, эта точка считается находящейся под контролем/огнём противника, даже если движок всё ещё показывает её как neutral.

В лог пишется:

```text
POINTSTART LOST squad=... flag=f... -> HOSTILE evenIfNeutral=true
```

После этого:

- новый `pointstart`-отряд на эту же точку не вызывается;
- точка исключается из списка обычных незахваченных нейтралов;
- она учитывается как вражеское направление;
- основные БТГ могут выбрать её как цель атаки;
- обычная пехота/танки получают право атаковать этот всё ещё neutral-флаг, потому что бот пометил его как `HOSTILE`.

Это сделано специально, чтобы бот не зацикливался на повторной отправке лёгких захватчиков в место, где первый отряд уже был уничтожен.

## Strategic neutral

В v1.11 используются два количества нейтральных точек:

```text
Nraw       = сколько neutral показывает сам BotApi
Nstrategic = neutral без точек, помеченных HOSTILE
```

Например:

```text
Nraw=2 Nstrategic=0 HOSTILE=2
```

означает: движок ещё считает две точки нейтральными, но оба направленных туда pointstart-отряда погибли, поэтому бот рассматривает обе точки как позиции противника и может переходить к основной атаке.

## Что осталось от v1.10

Сохранены:

- геометрия `_flag_points_final.json`;
- `_map_points_index.json` для определения стороны спавна;
- fuzzy map matching;
- поддержка нескольких координат одного имени `f*`;
- две независимые БТГ;
- восстановление пехоты/танков;
- tank-loss continue;
- 2-минутная проверка результата атаки;
- AA/defense;
- специальные авиационные реакции;
- только проверенные команды BotApi.

## Ожидаемые строки теста

На старте:

```text
START v1.11
ROLE pointstart candidates=...
POINTSTART PLAN points=... squads=... candidates=...
RULE opening-capture=pointstart-ONLY one-squad-per-start-point=ON recon-neutral-capture=OFF
```

Для каждой точки:

```text
QUEUE role=pointstart target=f...
SPAWN OK role=pointstart ... target=f...
ARRIVED squad=... role=pointstart target=f...
ORDER squad=... flag=f... role=pointstart
```

Успех:

```text
POINTSTART CAPTURE DONE squad=... flag=f...
```

Гибель по пути:

```text
POINTSTART LOST squad=... flag=f... -> HOSTILE evenIfNeutral=true
```

После этого статус должен показывать уменьшение `Nstrategic`, даже если `Nraw` ещё не изменился.

## Установка

Файлы из `BOT_GPT/v1_11/` копируются как актуальная версия в:

```text
resource/script/multiplayer/
```

Нужны:

- `bot.lua`
- `bot.data.lua`
- `bot.main.lua`
- `bot.mapdata.lua`
- `_flag_points_final.json`
- `_map_points_index.json`

JSON-файлы геометрии остаются теми же, что использовались для v1.10.
