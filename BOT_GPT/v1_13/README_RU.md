# NEU BOT v1.13

Основа — v1.12 hotfix, коммит ecc6b6bbf4a7be592dc188e487b5f7baa283915e.

## Правила и исправления

- Начальный захват: только `pointstart`, один отдельный отряд на каждую стартовую нейтральную точку. После захвата отряд не переназначается.
- Неудачный Spawn повторяется с паузой, пока вызов не принят или точка не сменит владельца. Лимит 20 циклов убран. Без кандидатов с тегом pointstart подмена другими юнитами запрещена, ошибка выводится в лог.
- Гибель pointstart до захвата помечает направление вражеским даже при нейтральном флаге. Новый стартовый отряд туда не отправляется.
- Две БТГ создаются независимо от появления разведки. Атака разрешается после завершения стратегической нейтральной фазы и открытия прежнего условия атаки: 300 секунд либо преимущество противника по эффективному числу точек.
- Один стартовый вертолёт получает маршрут по захваченным точкам противника (игрока). Если таких точек нет, ждёт. При неудачном Spawn используются повторные попытки критической роли; после гибели вертолёт не заменяется.
- Ожидание появления отряда устанавливается ДО Spawn. Синхронный GameSpawn больше не оставляет очередь заблокированной; повторный вызов Spawn внутри этого обработчика блокируется.
- События без squadId и повторные события уже зарегистрированного squad не забирают билет следующего вызова.
- Лимит подхвата спешенной пехоты больше не обнуляется при каждом повторном приказе для той же цели.
- Отложенный приказ танку проверяет актуальное состояние БТГ и использует её текущую цель.
- Захваченная ботом точка с устаревшей hostile-меткой не считается целью противника.

## Оптимизация

Список и индекс флагов вычисляются один раз за такт и очищаются после него. Расстояния между флагами и до спавна кешируются до следующей загрузки карты. Сообщение ATTACK GATE OPEN выводится при открытии, а не ежесекундно. Окно подхвата пехоты продлевается без пересоздания и повторного логирования. Сохранён cooldown одинаковых приказов.

## Установка

Скопировать четыре Lua-файла в `resource/script/multiplayer/` мода, заменив файлы установленного бота. Оба JSON из этой папки скопировать рядом с ними. Настройки — в bot.data.lua, включая имя папки мода ModFolder.

JSON включены без изменения содержимого из BOT_GPT/v1_8: `_flag_points_final.json` и `_map_points_index.json`.

## Проверка и ограничения

`tests/regression.lua` — сценарии с имитацией BotApi; запуск из папки версии: `lua tests/regression.lua`. Выполнены проверка синтаксиса четырёх Lua-файлов и сценарии в Lua 5.4: отсутствие recon, синхронное появление, длительные отказы pointstart, отсутствие дублирующих назначений, патруль вражеских точек, повреждённые/повторные события, гибель захватчика, переход двух БТГ к разным целям, лимит подхвата пехоты, кеши.

В самой игре версия ещё не проверена. Новые команды BotApi не добавлены. CaptureFlag задаёт вертолёту цель, но фактическую траекторию и прибытие этот API не подтверждает.

Подхват спешенной пехоты остаётся эвристикой v1.12: неизвестный squad во время атаки распределяется между активными БТГ. Это не подтверждённая связь с родительским БТР. При ожидающем билете Spawn неизвестный squad всё ещё может быть принят за заказанный; без подтверждённых полей корреляции GameSpawn безопасно устранить эту неоднозначность нельзя. Если принятый Spawn вообще не присылает событие, очередь продолжит ждать: слепой timeout с повторным заказом нарушил бы правило одного отряда на точку.

Алгоритм выбора карты и координат-дубликатов сохранён из v1.12; кеширование не исправляет неоднозначную геометрию исходных JSON и не подтверждает физическую близость точек. Для проверки нужен игровой game.log.
