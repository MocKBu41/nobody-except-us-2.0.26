# NEU BOT 2.0.4
Статус: **ПРОЙДЕНЫ МОДЕЛЬНЫЕ ТЕСТЫ; НУЖЕН ТЕСТ В ИГРЕ**.

Основа: существующий BOT_GPT/v2_0_3, snapshot main 11db92a2cb082a2177e570ae267735451f009e87.
Последние игровые испытания в LOG относятся к 2.0.2; нового боя 2.0.3 при подготовке не найдено.

## Изменения относительно 2.0.3
- Таймаут SpawnRetry считается с первой разрешённой попытки вызова, а не с постановки в очередь. Последние флаги и основной infantry больше не пропускаются только из-за ожидания более 60 секунд.
- Основной OPENING не создаёт новые заявки, пока действует MainOpeningFrozen.
- До выпуска БТГ каждый ещё не наш стартовый флаг перепроверяется на наличие живого назначенного захватчика. Погибший захватчик заменяется на том же флаге.
- CaptureFlag, вернувший false или Lua-ошибку, не засчитывается как выданный приказ. Повтор для того же живого отряда выполняется с интервалом не менее 15 секунд.
- OPENING / POINTSTART / ORDER включены в telemetry; session, event, snapshot и geometry_index обозначены 2.0.4. При новом бое сбрасываются состояние блокировки и период снимков.
- Сохранены Event Subscribe, обычная пехота как fallback, независимый стартовый helicopter, визуализатор и все три координатных индекса.

## Установка
Скопировать из этой папки в папку мода `resource/script/multiplayer/` с заменой:
`bot.main.lua`, `bot.lua`, `bot.core.lua`, `bot.logic.base.lua`, `bot.logic.lua`, `bot.geometry.lua`,
`_flag_points_final.json`, `_spawn_points_index.json`, `_map_points_index.json`.

`tests/` в игру копировать не нужно.
Открыть `bot_visualizer.html` в браузере и загрузить **bot_gpt_telemetry_a.jsonl** или **bot_gpt_telemetry_b.jsonl** из нового боя. Дополнительный JSON координат не требуется. При нескольких совпадающих картах выбрать фактическую.

## Проверка
Для карты с 11 нейтральными флагами:
1. `BOT 2.0.4 EVENTS ACTIVE` и `OPENING POINTSTART queued=11`.
2. Отдельные `POINTSTART ORDER ... flag=f1...f11`.
3. `OPENING COVERAGE COMPLETE assigned=11/11 -> RELEASE MAIN BTG`.
4. Затем основной `infantry -> recon -> tank -> mech_inf`.
5. При отказе приказа: `ORDER REJECTED`, затем `via=capture_order_retry`.
6. При гибели стартового захватчика до выпуска БТГ: `OPENING COVERAGE LOST` и новый отряд на тот же флаг.

Выполнены проверка синтаксиса шести Lua-модулей и tests/opening_regression.lua под Lua 5.4 с имитацией BotApi:
11 флагов с ожиданием 77 секунд, вертолёт без callback, fallback infantry, отказ CaptureFlag и повтор без дубликата, смерть захватчика, уже наш флаг, повторный старт, telemetry, синхронные callbacks и списание BP.

## Границы проверки
Реальная совместимость движка требует игрового теста. Отсутствие ошибки/false при вызове CaptureFlag означает лишь выдачу команды: достижение и захват точки этим не подтверждены.
Унаследованные ограничения: исчезнувший GameSpawn наземного вызова может удерживать AwaitingArrival; поздний callback отдельного helicopter не сопоставляется надёжно без идентификатора запроса. Эти случаи не объявляются исправленными.
Физическое движение по координатам, дистанции развёртывания и безопасная высадка остаются неподтверждёнными.

После боя сохранить game.log и обе telemetry в LOG с номером версии.
